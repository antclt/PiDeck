# 项目资源管理 / MCP 页改进清单

> 状态：**待排期**。来源：2026-10-04 pi 1.0 适配手工验收（`pi-1.0-adaptation-test-plan.md` 执行记录）中发现的问题与产品想法，按用户要求单独成文供排期。每项注明触发位置与建议方向；动手时逐项勾掉并回填状态。

## P1 · 正确性/一致性

1. ~~**`.pi/mcp.json` 保存无版本校验**~~ **已修复（2026-10-04，269bdde6 之后的后续提交）**：快照携带可写层内容哈希（`revisionOf`），保存回传比对；不匹配拒绝覆盖、提示并自动重载磁盘内容。全局层改走 `writePiConfigFile`（锁内重读，顶层未知字段保留）；项目层保存前预检（临时文件 rename 流程不变）；`missing` 哨兵支持从无到有写入（顺带修了内置扩展开关对无 settings.json 用户首次开关必冲突的隐藏问题）。
2. **「pi 内置扩展」对未信任项目的错误呈现** — 项目未信任时面板直接显示裸 IPC 异常（`Error invoking remote method 'pi-resources:summary'…`）。信任门禁本身正确，缺降级 UI：应显示「项目未信任」提示 + 引导去信任。（同日已另修 `isProjectTrusted` 未注入导致信任了也报错的接线 bug。）
3. **「检测」vs「检测连接」命名混淆** — 编辑区的「检测」是轻量可达性探测（结果「可达/不可达」，措辞已合规），连接状态面板的「检测连接」才是真实 `pi mcp list`。建议轻量的改名「检查可达性」或合并展示。

## P2 · 信息架构 / 布局

4. **MCP 页布局**（用户反馈「按钮位置太靠下」）：「检测连接」「导入」等高频操作在页面下半部；重构时把状态与操作上提。
5. **删除继承条目的反馈**：项目资源管理里删除只改草稿，列表行要等保存才消失且无「待删除」标记。彻底做法需区分「本层定义被删（待删除）」vs「删覆盖回到继承（必须继续显示）」，涉及数据模型，放进重构一起做。
6. **`auth.provider` 无创建入口**：UI 只在 server 已有该字段时展示说明，新建/编辑表单给不了；只能手改或导入。
7. **「登出」按钮对无 OAuth 的 http server 也显示**（如 `beui`），容易误点。
