# MCP 配置表单重排

> 状态：本次 UI 改动已实现并验证。本文记录当前实现，不代表最终的 MCP 服务目录方案。

## 当前界面

页面保持两栏：左侧为已配置服务器列表，右侧为智能添加或所选服务器详情。详情按以下顺序呈现：

1. **基本信息**：名称、传输方式，以及 HTTP URL 或 stdio 命令和参数。
2. **连接与认证**：连接检测、状态及 OAuth 登录/登出操作。HTTP 全局配置提供“自动 / API Key / 供应商登录”。
3. **启用**：服务器启停开关。
4. **高级**：HTTP 请求头或 stdio 环境变量、工具暴露方式、按工具覆盖、超时和 stdio 工作目录。

OAuth 客户端参数不通过普通表单编辑；从 JSON 或源文件导入的字段应原样保留。服务器列表框纵向填满左栏，不再显示额外配置层标签区。

## 已知边界

- 当前 API Key 表单只实现 `Authorization: Bearer <key>`。它不能代表所有 MCP 服务的 API Key 约定；例如有的服务要求自定义 HTTP header，有的 stdio 服务要求环境变量。常用服务模板应自己声明所需输入及写入位置，不能让用户猜。
- `auth.provider` 是复用 pi 模型供应商凭据，不等于 MCP 服务商登录；应作为特殊高级能力呈现。
- 独立 `pi mcp list` 状态不等同于某个正在运行会话的实时状态。

后续 UX 应优先研究“选择服务并填写该服务声明的必要输入”，同时保留 URL、命令、JSON 导入和 pi 原生高级配置作为通用兜底。服务目录中的接入方式需要逐项依据服务商官方文档维护。
